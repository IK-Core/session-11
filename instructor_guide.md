# RECODE Session 11 instructor guide

Start with a blank canvas. Students choose their own idea, purpose, objective, and deliverable. The optional inspiration button reveals diverse examples without selecting or inserting a project.

Help vague ideas become practical using audience, needs, constraints, and the smallest useful version. Do not require business deliverables from unrelated projects. Ask students to revise the idea in their own words.

Use the seven stages flexibly: IDEA (10 minutes), PLAN (10), RESEARCH (10), BUILD (30), TEST (10), IMPROVE (10), PRESENT (10). These are suggestions, not a countdown. Spend the largest block building something tangible. A useful first version is appropriate when the full project takes longer than one session.

The prompt editor begins empty at every stage. Teach context, objective, constraints, specific output, and missing information. Students use Copy Prompt and their own ChatGPT chat. No AI integration or automatic prompt generation is present. Prompt versions and personal reflections make the student’s process visible.

Ask for evidence: an attached file, saved text/code artifact, or accessible link to actual work. Read the planned output, actual output, incomplete work, test results, and changes. An artifact inventory alone is not proof of completion. HTML previews are isolated in a sandbox; students can download and run their prototypes independently.

## Instructor-reviewed rubric: 100 points

| Criterion | Points | Review focus |
| --- | ---: | --- |
| Idea and objective | 10 | Student ownership, purpose, and achievable objective |
| Plan and scope | 15 | Practical steps, constraints, and useful session scope |
| Research and verification | 10 | Appropriate sources, checks, and alternatives |
| Practical output | 30 | Tangible work, usefulness, execution, and effort relative to the objective |
| Testing and improvement | 20 | Real tests, honest findings, and responsive revisions |
| Independent thinking and presentation | 15 | Personal decisions, critical AI use, clear showcase, and next steps |

Judge quality and effort yourself. Do not award marks for matching keywords or simply filling fields. Apply each criterion appropriately to the student’s project. Discuss gaps in evidence before deciding a score. Stage checkmarks are self-reported readiness only.

## Review and return work

1. Ask the student to export the full JSON project and share any larger externally stored files.
2. Export any project already open on your device before importing a student project. Import requires confirmation because it replaces the browser checkpoint.
3. Open the instructor desk and use View project and evidence. The showcase includes original and revised ideas, final work, output evidence, and a full notebook/prompt record.
4. Enter a whole-number score within each criterion’s range, your name, and feedback. Finalize the review when all six scores are present. The app adds the instructor’s entered points; it never assigns points itself.
5. Export the reviewed JSON and return it to the student. They can import it and continue. Evidence changes mark the prior review as needing an update. Feedback remains available.

The instructor desk has no authentication and is not a secure gradebook. File exchange is manual. Browser saving can be unavailable or reach its quota; exports are the portable backup. Keep one project tab open at a time. There is no central student collection or account system.

The Markdown summary is a readable record. The full JSON includes the editable notebook, prompts, artifacts and attached files. Print the showcase to save a PDF if needed.
